1.1 Problem Statement

Why secure attendance matters

  • Attendance decides exam eligibility, so a wrong record has real consequences for students and for the institution.
  • Manual roll call takes several minutes of every class and is easy to fake: a friend answers for an absent student, or a name is added to the sheet later.
  • A plain, fixed QR code makes things faster but not safer. It can be photographed and forwarded, scanned from anywhere, and reused in later classes.
  • Records kept in a spreadsheet or database can be edited afterwards by anyone with access, and nobody can tell.

Formal statement

Design and implement an attendance system in which only a student who is physically present, using their own registered device, can mark attendance for the current class, in which every record is tamper-evident, and in which the final attendance report can be verified by a third party without trusting the database.

1.2 Our Project Response

ProblemHow the system addresses it
Forwarded or old QR codesQR changes every 10 s and is authenticated with HMAC-SHA256; tokens older than one window are rejected.
Proxy using a friend's passwordEach account is bound to one phone's ECDSA key; every scan must carry that phone's signature.
Captured requests sent againSigned timestamp (±60 s) and a single-use nonce per scan.
Editing records afterwardsSHA-256 hash chain over all records; the admin integrity check pinpoints the edited record.
Disputed or forged reportsEd25519-signed session reports that pin the chain head; verifiable offline with the public key.
Stolen passwords / database leakArgon2id password hashes, hashed session tokens, account lockout.
