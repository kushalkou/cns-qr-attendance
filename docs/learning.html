Learning

Learning Outcomes

Through the Secure QR-Based Attendance System project, we gained practical experience in applying cryptographic primitives to a working client–server system and in testing it against realistic attacks.

  • Message authentication: Used HMAC-SHA256 to make QR tokens that only the server can produce, and learned why a plain hash is not enough when the attacker knows the input format.
  • Key derivation: Used HKDF-SHA256 to derive independent per-session and key-wrapping keys from one master key, so a leaked derived key exposes nothing else.
  • Digital signatures: Used ECDSA P-256 in the browser for device binding and Ed25519 on the server for reports, and compared why each fits its place (browser support versus deterministic, misuse-resistant signing).
  • Freshness and replay protection: Combined time windows, signed timestamps and single-use nonces, and saw how each one alone leaves a gap.
  • Tamper evidence: Built a SHA-256 hash chain over attendance records and anchored its head inside signed reports, so even an attacker who recomputes the chain is detected.
  • Secure password storage: Stored passwords with salted, memory-hard Argon2id and added account lockout against online guessing.
  • Web security: Configured TLS, HttpOnly/Secure/SameSite cookies, a strict Content Security Policy and role-based access control, and understood which attack each one stops.
  • Web Crypto API: Generated non-extractable keys on the phone, stored them in IndexedDB and converted signatures between the raw (r‖s) and DER formats.
  • Security testing: Wrote an automated red-team script that replays, forges, proxies, brute-forces and tampers with the live system, and wrote a threat model stating honestly what the system does not protect against.
